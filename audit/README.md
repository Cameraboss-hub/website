# Migration audit evidence

The report is `../MIGRATION-AUDIT.md`. `evidence/` is the frozen, local-only 9 September 2026 audit snapshot and is ignored by Git. It contains URL-by-URL results, metadata comparisons, file hashes, build/check logs and browser observations. It contains no environment values or gallery PINs.

These are report-generating scripts, not a release approval or an installed ongoing monitor. Do not interpret exit code 0 as proof the migration has passed; inspect the summaries and unresolved responses. Metadata-differences, browser observations, backlink sample, inventory and the written report are frozen evidence, not regenerated by the scripts below.

For a new comparison, run the app build first. From the independent repository root, `python3 audit/audit.py` reuses cached public-page observations and compares the latest build. `python3 audit/audit.py --refresh` fetches a new live baseline and overwrites those evidence results. Archive the existing snapshot before refreshing. `python3 audit/assets.py` checks referenced URLs with HEAD; `python3 audit/recheck.py` retries apparent 404s and an owned-host timeout with GET. `python3 audit/content-audit.py` also checks local HTTP responses and expects the independent preview on port 3200.

The scripts perform read-only network requests and write only their local evidence directory. They do not deploy, submit enquiries, migrate galleries, modify the database, or change DNS. Access blocks, timeouts and unsupported redirects remain unresolved rather than being treated as success or confirmed missing pages.

## Website-first repair checks

Use `npm test`, `npm run check` and, with port 3200 running, `python3 audit/verify-repairs.py`. The older scripts above preserve assumptions from the pre-repair audit, including the old gallery routes; do not use them as current sign-off checks without updating those assumptions. `repairs-http.json`, `image-savings.json` and `repair-*.log` describe the repaired copy.
